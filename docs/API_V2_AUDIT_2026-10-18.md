# UniEngine API 收口审计(v2.0.0 方案,待拍板)

> 状态:设计稿,未实施,由业主拍板
> 日期:2026-10-18
> 基线:master `0c4d0ff`(77 个 TUniEngine 导出方法;272 单测;覆盖率 90.1%)
> 目标:配合 `v2.0.0` tag 一次性收口 API 面——Deprecated 归位、命名归一、移除留 v3

---

## 1. 审计原则

1. **v2 = 集中破坏性变更窗口**:此刻下游尚未按新契约固化,改动成本最低;v2 之后进入稳定期,v3 前只加不改。
2. **下游编译成本优先**:本库有两个已知消费形态——downstream-project(GOPATH 直编,无版本锁)与模块化引用者。任何"删字段/删方法/改签名"都会在下游编译期爆炸;**标 Deprecated(零编译成本)优于移除**。
3. **改名不破坏隐式实现**:接口类型改名只要方法集不变,实现方(隐式实现)零改动——Rename 成本仅落在显式引用类型名的代码。
4. **每个 Deprecated 必须带去处**(指向替代 API 或"无替代,纯遗留")。

## 3. 处置建议

### 3.1 B 档:v2 标 Deprecated(保留,零编译成本)

> `DecryptResult` 已按 D5 在 v2 直接删除，不属于本表“保留项”；见 §3.3 D5。

| 项 | 现状与理由 | 建议去处 |
| --- | --- | --- |
| `SpecialInsertL/LCtx/P/PCtx` | 4 个废弃别名(CopyIn* 的旧名);**已有 Deprecated 标注与测试**,下游仍有引用则编译安全 | 保留标注;v3 视下游迁移进度移除 |
| `HasSpecialGetSqlInsertL`/`HasSpecialSetSqlValuesL` | 废弃接口对,引擎仍探测 | 同上,成对保留 |
| `ExistConst` | CtDF 约束按列名匹配有歧义(已由 `ExistConstOn` 精确修复,On 内部其它约束类型仍委托它) | 标 Deprecated 指向 `ExistConstOn`;实现保留(On 的内部依赖) |
| `DefaultPageSize`/`SpecialPageSize` | UI 分页辅助,与批量写入(normalizeBatchPageSize)已解耦;已有 `TestDeprecatedPagingWrappers` 钉住废弃语义 | 维持现状(已属废弃姿态),文档补"仅 UI 分页用" |
| `TUniEngine.Instance`/`.DataUser`/`TUniTable.ParentTab` | Deprecated 字段(设置无效);**下游有赋值语句**,移除会破坏编译 | v2 保留标注;v3 移除 |

### 3.2 保持不动(核心面,不建议动)

查询/写入/COPY/事务全套(含 Ctx 约定:非 Ctx=便捷封装)、WithTx、注册族、元数据族、Secret/SecretDefault/IsEncrypted/VerifySignRow、GetTable/GetTableByClass(两个访问器各有键语义)、ListSecretTable、AutoKeys、GCMOpen(自定义 SecretHook 实现者的 GCM 原语,小而稳定)、RunDebug/ProviderName/Initialize、PrepareTables/PrepareRunSQL、IfDropView、VerifyUnkeyed(文档化风险开关,有测试)。

**理由**:这些是 272 个测试与四~六方言真机矩阵钉住的主体;v2 动它们只会制造迁移成本,无质量收益。

## 4. 建议不纳入 v2 的项(记录在案)

- **TUniTable 公开可变字段私有化**(HashField/HashPkeys/ListField/ListPkeys/ColSecret/ColVerify):GetTableByClass/GetTable 已提供持锁访问,但字段私有化会破坏一切直接读字段的下游——v3 议题;
- **Supplier 字段最终退场**:PolarDB→COPY 路由仍依赖它;待 BatchDialect 式显式字段方案覆盖全部用途后再议;
- **Ctx 强制迁移/非 Ctx 移除**:便捷封装是既定契约;
- **命名风格重写**(PascalCase/this/eror):ROADMAP 已明确不做。

---

## 5. 拍板后的执行顺序(供参考)

1. 按 D1-D5 决策落地(预计全部为标注/文档/少量新增常量,零行为变更);
2. CHANGELOG"破坏性变更/废弃"两节终稿;
3. `v2.0.0` tag + 推送;
4. 下游按"旧调用方接入检查清单"自查(重点:D2 若改值、Special* 迁移意愿登记);
5. v3 待办入 ROADMAP(Special*/Instance/DataUser/ParentTab 移除、字段私有化;`DecryptResult` 已在 v2 删除)。
