# UniEngine 可提分项

> 基线：`CODE_QUALITY_REVIEW_2026-10-14.md` 对提交 `85c4ad1` 的六维评分为 **87/100**。当前工作区正在把 SQL Server 占位符检查改为开发者声明的 `ProvideName × ColParam` 配置检查；该变更应完成测试后再纳入下一次评分。以下收益是工程估计，项目之间有重叠，不能直接相加。

## 建议优先级

| 优先级 | 可提分项 | 当前依据 | 完成标准 | 主要收益 |
| --- | --- | --- | --- | --- |
| 高 | 调试日志实参脱敏 | `UniEngine.go` 的 `sqlDebug` 在 `RunDebug(true)` 时直接打印全部参数，普通列可能含个人信息 | 默认仅记录 SQL 模板、参数个数和错误信息；实参输出须显式开启且可脱敏；回归断言日志不含敏感值 | 安全性与易用性 |
| 高 | SQL Server 驱动配置防错 | `ProvideName` 由开发者指定；静态检查无法确认它与 `sql.Open` 或连接器的真实模式一致 | 提供明确的装配示例或构造入口，把 `Db`、`ProvideName`、`ColParam` 一起配置；两种驱动模式的真库读写与错误组合测试持续运行 | 正确性与数据完整性 |
| 高 | 存量 MAC v1 数据迁移 | 新写入已默认用 `MAC2:`，旧 `MAC:` 行仍按 v1 验签 | 统计 v1 行数，分批重签，最终确认受保护表无 v1 行；保留回滚与异常行处理记录 | 数据完整性；完成 Q1 条件销账 |
| 中 | 统一 PolarDB 批量路由 | `InsertP` 仅凭 `Supplier==DtPOLODB` 选择 COPY，其他方言逻辑看 `Provider`；两者误配会改变行为 | 明确单一权威字段，覆盖 `Provider=DtPOLODB`、普通 PostgreSQL 与错误组合的回归；更新兼容说明 | 正确性与架构 |
| 中 | 隔离事务归属 | `tx/inTx` 挂在共享 `TUniEngine` 上，事务期间依赖调用方串行 | 设计局部事务对象或 `WithTx`；并发事务互不串扰，提交、回滚与取消的真库测试通过 | 正确性与并发安全 |
| 中 | 降低锁争用 | `BeginTx`、`Commit`、`Rollback` 持引擎写锁；每次表锁获取还经过包级 `muLazy` | 先测并发延迟与吞吐，再缩短持锁网络调用并消除热路径全局锁；`-race` 与基准均通过 | 性能与资源管理 |
| 中 | MySQL `SaveIt` 回退原子性 | MySQL 与自定义钩子路径仍采用 count-then-write，两步间可被并发写入改变结果 | 明确唯一键与冲突重试语义；真库并发用例证明不会静默覆盖或重复插入 | 正确性 |
| 持续 | 方言边界与批量写入语义 | 非默认 schema、分页中途失败及部分成功仍是高价值边界 | 针对真实用例补测试并写明调用方可依赖的成功范围；避免只追求覆盖率数字 | 测试与文档 |

## 实施顺序

1. 先做日志脱敏和 SQL Server 装配防错；两项直接影响生产数据安全，改动范围相对小。
2. 同步推进 v1 行清点与迁移。该项是部署工作，代码测试通过并不能代替实际数据迁移。
3. 修正 PolarDB 路由，再处理事务对象与锁粒度；后者需要独立设计和并发基准。
4. 最后按实际业务使用面补齐 MySQL 并发写入、schema 与分页失败场景。

## 评分口径

本清单沿用质量评估报告的六维模型：正确性与可靠性 25%、安全性与数据完整性 25%、架构与可维护性 15%、测试与工程保障 15%、性能与资源管理 10%、文档与易用性 10%。评分只在修复落地并完成相应验收后调整；存量数据迁移必须以实际行数清零作为证据。
