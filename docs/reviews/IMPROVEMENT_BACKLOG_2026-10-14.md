## 1. 评估模型（先读这里，否则下面的分数看不懂）

七维加权，满分 10。权重与含义：

| 维度 | 权重 | 关心什么 |
| --- | ---: | --- |
| 功能完整性与设计 | 20% | 能力覆盖、方言抽象、API 契约是否自洽 |
| 正确性与健壮性 | 20% | 是否存在静默错误/数据损坏/panic/卡死；边界是否闭合 |
| 安全性与数据完整性 | 15% | 注入面、加密与验签保证、密钥管理 |
| 并发安全 | 10% | 数据竞争、锁语义、共享状态契约 |
| 测试与 CI | 15% | 用例质量（是否真断言）、覆盖率、真库验证、CI 门禁 |
| 代码风格与可维护性 | 10% | 一致性、死代码、可读性、职责划分 |
| 文档与工程化 | 10% | 文档是否与实现一致、迁移路径、贡献指南 |

> **模型不含"性能与资源"维度**。热路径优化在当前模型下**几乎不加分**——见 §3.4 的说明（是否引入属于模型变更）。

## 3. 可提分项

### 3.1 T2 · 中等改动（做完 → 约 **8.5**）

#### 3.1-1 `sqlDebug` 实参脱敏 + 可注入日志接口

| 项 | 内容 |
| --- | --- |
| 维度 | 安全性与数据完整性（8.0 → 8.3） |
| 现状与证据 | `UniEngine.go:316` `sqlDebug()` 直接 `fmt.Printf("UniEngine: %s.val: %v\n", Kind, Args)`。开启 `RunDebug(true)` 后**所有实参**写入 stdout：secreton 列是密文（可接受），但**非加密列（姓名/手机号/身份证等）是明文**；且只能输出到 stdout，无法接 zap/logrus 做脱敏与分级 |
| 建议 | ① 默认只输出 `SQL + 参数个数 + 耗时`；实参值需显式 opt-in（如 `DebugMode` 位掩码）；② 提供 `Logger` 注入点（`func(format string, args ...interface{})` 或接口），默认落到 stderr |
| 验收 | `RunDebug(true)` 后的日志**不含实参值**；注入的 Logger 能收到 SQL、参数个数与耗时；secreton 列与普通列一视同仁 |
| 成本 / 风险 | 小 / 低（纯输出侧改动，但会改变现有调试日志文本，属可接受的可观测性变更） |

#### 3.1-2 锁粒度：事务终结与包级初始化锁

| 项 | 内容 |
| --- | --- |
| 维度 | 并发安全（8.0 → 8.5） |
| 现状与证据 | ① `BeginCtx`/`Cancel`/`Commit`（`UniEngine.go:416/439/459`）在 `lockTables()`（`UniEngine.go:121` = 包级 `muLazy` + 引擎写锁）**持写锁期间做网络往返**（`BeginTx`/`Rollback`/`Commit`），期间该实例上所有并发查询被阻塞在一个 RTT 上；② `lockTables`/`rlockTables` 每次都先取**包级** `muLazy`（`UniEngine.go:111` `initLock()`），同进程内多个引擎实例互相争用 |
| 建议 | ① 事务终结改为「锁内取出 `*sql.Tx` 并清理状态 → 释放锁 → 锁外调用 `Commit/Rollback`」；② `mu`/`secret` 的懒初始化改用 `sync.Once` 或构造期初始化，从热路径移除全局锁 |
| 验收 | `-race` 下并发 `Select/Insert` 与 `Commit` 无竞争；新增 `BenchmarkConcurrentSelect`（多引擎实例）显示锁竞争与原实现有量级差异；既有事务语义（重复 `Begin` 拒绝、终态回收、原始错误上抛）全部不变 |
| 成本 / 风险 | 中 / 中（事务语义敏感；必须保留 Q3 修复后的终态语义与 `ErrAlreadyInTransaction` 契约） |

#### 3.1-3 `Supplier` 并入 `Provider` 语义

| 项 | 内容 |
| --- | --- |
| 维度 | 功能完整性与设计（8.5 → 8.7） |
| 现状与证据 | `insertPage`（`UniCopyIn.go:191`）只认 `this.Supplier == DtPOLODB` 决定 `InsertP` 走 COPY 还是多行 INSERT；而 `Supplier`（`UniEngine.go:71`）**引擎从不赋值**、README 未记载 ⇒ 按文档配 `Provider=DtPOLODB` **拿不到 COPY 快路径**；反之 `Supplier=DtPOLODB` 配非 PG 族 `Provider` 会让 `InsertP` 直接报错（`CopyInL requires a PostgreSQL-family provider`）。方言其余分支一律只看 `Provider`（`dbFamily()`） |
| 建议 | `insertPage` 改判 `this.dbFamily() == FmPOSTGR && this.Provider == DtPOLODB`；`Supplier` 标注 Deprecated（或由业主决定在破坏性版本中移除）；README 的 PolarDB 说明补一句 COPY 路径由 `Provider` 决定 |
| 验收 | 只设 `Provider=DtPOLODB` 时 `InsertP` 走 COPY；未设 `Supplier` 不再影响任何路径；误配不再导致 `InsertP` 失败 |
| 成本 / 风险 | 小 / 低-中（改变 `InsertP` 的路由条件，需同步 `TestInsertPPolarSupplierRoutesToCopy` 的口径） |

## 5. 不建议做的（伪提分 / 负收益）

以下几条**看起来能提分，实际会降分或破坏契约**，列出以免后人重复尝试：

1. **为覆盖率数字写无有效断言的测试**。外部评审 §5.2 已明确反对；当前 88.0% 是实测值，门槛 80% 留 8 点余量已足够。
2. **把结构体入口的 NULL 改成静默零值或跳行**。前者会把 `NULL` 变成 `""`/`0`（判空与统计语义出错），后者会让调用方无法区分"本来没有这行"与"这行读不动"。当前已把"引擎不做静默降级 + 标量入口 `SelectS/SelectD/SelectF` 相反地宽容"写成明确契约（`README.md` §3 与 `doc.go`），改动属**正确性下调**。
3. **删除 `EtDelete` 公开常量**。该分支已实现并被 `PrepareRunSQL` 使用；删除属破坏性且无收益。
4. **为 SQL Server 寻找"通用 `ColParam`"**。已实测：`mssql` 与 `sqlserver` 驱动名下**不存在通用取值**（`@p` 在 `mssql` 下报 `expected 0 arguments`；`:`/`$`/`?` 在 `sqlserver` 下报语法错误或静默写错）。只能"文档 + 初始化期哨兵回显自检"，两者均已落地。
5. **删除 `SpecialInsert*` 废弃别名**。破坏源码兼容，收益仅为"少几个函数"。
6. **给 `pkeyFields()` 再加 `ReadOnly` 过滤**。业主已判定不需要：`db:"-"`/`db:"_"` 标记字段已**无法登记为主键**（`SetKeys` 源头拒绝 + `RegisterPkeys` 白名单），再加一层只是重复防护；而 `db:"col,readonly"` 有真实列名，本就应该参与定位。
7. **硬删 4 个已标 `Deprecated` 的字段**。会让外部代码编译失败；除非业主决定发破坏性版本（当前保留字段 + 明确"设置无效"是成本最低的处置）。
