## 1. 当前基线

已具备：

- PostgreSQL / MySQL / SQL Server / Oracle / TiDB / 达梦真机测试
- 根模块 272 个单测，覆盖率约 **90.2%**
- CI：`build` / `vet` / `gofmt` / `test -race` / 覆盖率门槛 85% / 3 个 fuzz smoke
- 注册表一表多类、共享锁、COW 快照
- Oracle 100 行/页、达梦 100 行/页批量上限
- `WithTx` 引擎级闭包（context 版已放弃）
- `GetTableByClass` / `ExistConstOn` / 达梦 `Supplier` 批量预算
- 真机数据库名统一脱敏为 `UNIENGINE_TESTDB`

明确不做：

- context 版 `WithTx`
- `staticcheck` / `govulncheck` / `golangci-lint`
- 为了达梦把 `Provider` 改成 `DtDAMENG`（会破坏大量应用 `switch Provider`）
- PascalCase / `this` / `eror` 等历史风格重写

## 2. 下一阶段三条主线

### 主线 A：生产落地（最高优先）

目标：让 downstream-project 安全完成升级，而不是继续扩库功能。

| 优先级 | 工作 | 产出 |
|---|---|---|
| P0 | 修复生产审计报告中的 8 处确认缺陷 | `SelectD` 3 处吞错、`grow` 2 处未检查、`p4pz` 1 处、CSMS 2 处 `_ = SelectL` |
| P0 | 8 处 `HashTabl` 直读改为 `GetTableByClass` | 消除运行时注册的并发 map 风险 |
| P1 | 抽查 `SelectD` 热点文件 | 1134 处变量 SQL 中，优先 core/expd/flow/csms/myoa |
| P1 | 建立生产静态门禁 | 禁止 `SelectD/F/S` error 位为 `_`、`_ = SelectL`、`HashTabl[` |
| P1 | 升级回归 | 构建、启动注册、核心接口、`-race` 冒烟 |

验收：

- downstream-project 启动无 `ErrTableConflict` / `ErrUnregisteredClass`
- 8 处 `HashTabl` 全部替换
- 受影响接口无新增错误
- 至少一轮六库真机测试通过

### 主线 B：数据库矩阵与边界

目标：把“文档声称支持”变成“有真机证据”。

| 优先级 | 工作 | 说明 |
|---|---|---|
| P1 | 金仓 KingbaseES 真机 | `DtKINGES` 目前仅 PG 族复用，需验证 `information_schema`/UPSERT/占位符 |
| P1 | openGauss 真机 | 与 PG 有差异，重点验证 `ON CONFLICT`、`COPY`、元数据 |
| P1 | PolarDB 真机 | `Supplier=DtPOLODB` + `InsertP` COPY 路由 |
| P1 | Taurus 真机 | MySQL 协议差异；历史上适配中断，需确认 `float/double`、序列 |
| P2 | 达梦 CI service | 目前达梦真机靠自备实例，CI 未纳入 |
| P2 | Oracle 多 schema/同义词/物化视图 | 当前 `USER_*` 边界已文档化；按真实业务决定是否查 `ALL_*` |
| P2 | `ExistConstOn` 扩展到非 `CtDF` | 目前只解决默认值列名歧义 |

验收：

- 每个方言至少一组 CRUD + 批量 + 元数据真机用例
- 新方言只在 `Provider`/`dbFamily` 增加映射，不改应用 SQL 分支
- 失败场景有明确错误，不静默写错数据

### 主线 C：工程质量与 API 稳定

| 优先级 | 工作 | 说明 |
|---|---|---|
| P1 | 加密/验签密钥轮换 | 当前只支持单密钥；需要 key id/版本与迁移窗口 |
| P1 | 性能基准固定化 | 批量页大小、`SelectL` 扫描、COPY/INSERT ALL 分方言基线 |
| P2 | API 清理 | `Instance`/`DataUser`/`ParentTab`、`HasField`、`DecryptResult` 等废弃面 |
| P2 | 读写分离/重试 | 当前无内置；明确不做的边界，避免误用 |
| P2 | README 拆分 | 4k 行主文档拆为使用/方言/迁移/安全四份，降低漂移 |
| P2 | prepared statement 缓存 | 每查询 `PrepareContext`；是否引入缓存需基准证明收益 |

验收：

- 安全密钥可轮换，旧密文仍可读
- benchmark 有基线阈值，回归可发现
- 废弃 API 有迁移表；不破坏现有调用方

## 4. 评分视角

当前库本体约 **90/100**，主要失分不在功能，而在：

- 生产调用点尚未整改（外部代码，非库缺陷）
- 部分声称支持的方言缺真机证据
- 安全密钥生命周期不完整
- 历史 API/命名增加维护成本

建议不要继续加新功能；先把生产落地和方言矩阵做完，再考虑 v1.0 API 冻结。

---

## 5. 不建议现在做

- context 版 `WithTx`：需要改 3800+ 个事务块/函数签名，收益低于成本
- 全量 `SelectD` 1134 处审计：先热点 + 静态门禁，再逐步清理
- 全库风格重写：diff 大、风险高、不产生行为收益
- 为达梦改 `Provider`：应用 507 处 `case DtORACLE` 会受影响
